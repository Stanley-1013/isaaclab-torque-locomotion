# Design — SATA → Isaac Lab cross-engine migration (Go2 anchor, one-week course slice)

**Date:** 2026-06-01
**Status:** approved (verbal "Go", 2026-06-01); spine = Go2 cross-engine anchor,
new robot demoted to a stretch cherry
**Type:** follow-on applied project (separate resume centerpiece), spawns a NEW repo

## 1. Context & motivation

The SATA reproduction repo (`bio-inspired-adaptive-locomotion`, Phases 1–4
complete) observed that removing the bio-inspired torque layers (activation
low-pass, Hill force-velocity, motor fatigue, growth curriculum) *raises*
training reward in a clean sim, while the ablated policies leave the
hardware-realisable torque envelope (`no_activation` peaks 42.5 N·m vs Go2's
45 N·m limit; `no_fatigue` 2.5× energy / 35× jerk). That repo read this as the
bio layers behaving more like feasibility constraints than reward devices — its
own interpretation, not a settled fact, and none of it is load-bearing here;
this repo's question is purely cross-engine fidelity.

That repo runs on **Isaac Gym Preview 4**, now deprecated and unsupported.
**Isaac Lab** (built on Isaac Sim, same `rsl_rl` PPO backend) is the official
successor, with manager-based environments and built-in Go2 velocity tasks.

**This project** is a follow-on *applied* piece for a broad embodied-AI
portfolio (not tied to the marmotlab application). Priorities: **sim2real
(top) > RL (some) > control fundamentals (secondary)**; with no real robot,
"sim2real" = sim-to-sim / zero-shot OOD-dynamics transfer.

## 2. Goal of THIS slice (one week, to a course report)

Converged topic: **platform migration (Isaac Gym → Isaac Lab), anchored on Go2**,
carrying two honest scientific threads:

1. **Cross-engine reproducibility** — do the behaviours the SATA repo observed
   survive an engine change? Keeping **the same robot (Go2)** is what makes this
   clean: we have the SATA repo's known numbers (reward 104±16; the peak-torque
   metrics) as **a reference to validate the migration against** — a new robot
   would give no reference to tell a migration bug from a real difference.
2. **Cross-engine zero-shot transfer as a sim2real proxy** — the Isaac Gym →
   Isaac Lab engine gap (contact/friction/actuator-dynamics disagreement) is a
   free, legitimate proxy for the sim-to-real gap. Train under one engine,
   deploy zero-shot under the other, and measure the gap. Whether the bio
   layers help the policy survive the gap better than the ablated policies is an
   exploratory, motivated-but-out-of-scope question — it would not be testing a
   known mechanism, and the README §Framing already demotes it to out of scope.
   This only stays a clean controlled comparison **because the robot is fixed** —
   the only thing that changes is the engine.

A key sub-migration either way: Isaac Lab's stock Go2 task defaults to
**position (PD) control**; we configure **torque/effort control** to match
SATA's paradigm. That step is itself meaningful migration work and is the
prerequisite for the bio-layer port.

### Out of scope for the week (explicitly deferred — anti-over-claim)
- Full 4-layer bio stack (Hill + growth-curriculum tuning).
- A multi-scenario OOD study with 8-seed mean±std rigor.
- A second robot as the *spine* (it is only a stretch cherry — see §5).

## 3. Risk model

Two gating risks, both front-loaded:

**R1 — Isaac Sim/Isaac Lab install (Ops, Opus can't de-risk).** Getting Isaac
Sim + Isaac Lab running in the lab K8s container (no sudo, NFS `$HOME`, A6000),
training headless, and rendering to the existing TigerVNC/noVNC display. Worth
0.5–1.5 days with real blow-up potential. Sequenced first.

**R2 — obs/action contract matching (only for the zero-shot transfer, §4.4).**
`legged_gym`'s observation concatenation order/scaling differs from Isaac Lab's
manager-based ordering; loading an Isaac-Gym-trained policy into an Isaac Lab
eval env requires matching the obs/action contract exactly or the policy is fed
garbage. This is why the zero-shot transfer sits at the *top* of the ladder, not
the floor.

**Mitigation:** the fallback ladder (§5) makes each lower tier a self-sufficient
presentable result, so the talk survives if R2 (or R1's overrun) cuts the top.

## 4. Technical design

### 4.1 Environment
Reuse the existing VNC/noVNC pipeline from the SATA setup. Install Isaac Sim +
Isaac Lab under `$HOME` (NFS-persistent). Confirm the stock Go2 velocity task
trains headless and renders.

### 4.2 Native Go2 baseline (Tier 1)
Train Go2 on the built-in velocity task, configured for **torque/effort
control**, in Isaac Lab. Deliverable: a walking policy + reward curve + clip,
**validated against the SATA repo's known reward** as a migration sanity check.

### 4.3 Bio actuator + cross-engine reproducibility (Tier 2)
Port **the bio layers** — **torque action + activation low-pass + a fatigue
torque-capacity state** — as a custom Isaac Lab actuator (an `ActuatorBase`
subclass applied after the policy's torque output, a separable channel mirroring
the SATA structure). Train Go2 **with vs without** the bio actuator natively in
Isaac Lab; **we check whether the peak-torque behaviour observed in the prior
repo (peak joint torque kept inside the actuator envelope; lower jerk/energy)
also appears here.** (The "feasibility-envelope" framing was the prior repo's own
interpretation and was later dropped as the headline there — the finalized
headline is the reward reproduction, not an envelope claim — so it is not
load-bearing for this check.)

### 4.4 Cross-engine zero-shot transfer (Tier 3 — the headline, riskiest)
Load existing **Isaac-Gym SATA checkpoints** (rsl_rl ActorCritic; loadable since
Isaac Lab also uses rsl_rl) into an Isaac Lab eval env whose obs/action contract
is matched to the policy (R2). Run **zero-shot**, measure the engine gap
(reward/fall-rate/torque), and compare **reference (full bio) vs
no_fatigue/no_activation** to test whether the envelope helps the policy survive
the gap. Requires the §4.3 actuator to replicate the training-time pipeline at
eval.

### 4.5 New-robot generalization (Tier 3b — optional cherry)
If time remains, add one new quadruped (e.g. Anymal-C) trained natively to show
the method generalizes across morphology. Clearly preliminary.

### 4.6 Seeds & compute
4×A6000, shared — pin to confirmed-idle GPUs (CUDA_VISIBLE_DEVICES), good
lab-citizenship rules apply. Run seeds **concurrently across GPUs**. Seed count
is **resource-gated, not pre-committed**: floor 1–2; target **3–4** if D0–D1 go
smoothly and per-run wall-clock is reasonable. Caveat: **Isaac Sim is heavier
per-env and slower to start than Isaac Gym**, so last time's fast Isaac Gym
throughput does not transfer directly — "add seeds if runs are cheap", not a
promise. Comparisons reported **preliminary, sim-only, low-seed** unless the seed
count genuinely supports mean±std.

## 5. Fallback ladder (each tier is a complete, honest, presentable result)

## 6. Day-by-day

- **D0** — install Isaac Sim + Isaac Lab; verify stock Go2 task trains headless +
  renders to VNC. (R1 — front-loaded.)
- **D1** — Go2 torque-control baseline trained & walking, sanity-checked against
  the SATA reward → **Tier 1 secured.**
- **D2–3** — port core bio actuator; verify behaviour moves the expected way
  (peak-shaving / smoothing); with/without run → **Tier 2.**
- **D4** — attempt cross-engine zero-shot transfer (R2: match the obs/action
  contract, load checkpoints, measure the gap) → **Tier 3** if it lands.
- **D5** — slides + clips + curves; framing: cross-engine reproducibility +
  (if landed) zero-shot transfer; full bio stack + new robot = next phase.
- **D6–7** — buffer for R1/R2 overrun.

## 7. Deliverables

- A **new repo** (separate from the SATA repo) housing the Isaac Lab migration.
  (This spec lives in the SATA repo as the planning artifact; the new repo is
  created as the first plan step.)
- Trained Go2 policy/policies, reward + torque curves, rendered clip(s),
  and — if Tier 3 lands — a cross-engine transfer table.
- A short course-report deck reusing the SATA repo's presentation aesthetic.

## 8. Honesty / framing guardrails (carry over from the SATA repo)

- Don't over-claim: present a complete *slice*, name what's deferred.
- Sim-only; "within envelope" = within the rated torque number, not
  hardware-validated; the engine gap is a *proxy* for sim-to-real, not the real
  thing — say so.
- Low-seed results are preliminary; no 8-seed-style mean±std unless earned.
- Don't import the prior repo's bio-layer interpretation as a fact; this slice
  is about cross-engine fidelity, and that framing is not load-bearing here.
